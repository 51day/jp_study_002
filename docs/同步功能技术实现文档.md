> 版本：2026-10-30 · 适用项目：memorize-word（背单词 FSRS + AI）

本文档面向**开发者/维护者**，详细说明本次「Vercel + Neon PostgreSQL 离线优先自动同步 + 可复用通用微同步引擎」的实现细节、文件改动、架构设计与关键避坑点。

## 一、架构总览

采用**离线优先（offline-first）+ 微同步引擎（micro-sync engine）**架构：

```
浏览器 (React)                          服务端 (Vercel/Express)
┌───────────────────────┐               ┌──────────────────────┐
│ localStorage (离线可用) │               │ /api/sync/state       │
│   ↑ 写入自动 markDirty  │  ──推送──▶   │   (受全局密码中间件保护)│
│   ↓ applySyncPayload    │  ◀──拉取──   │        ↓               │
│ ClientSyncController    │               │ dbService (pg.Pool)    │
│  (防抖+批次+visibility)  │               │   app_universal_sync   │
└───────────────────────┘               │   (JSONB 单表 + 事务)   │
                                         └──────────────────────┘
```

核心思想：
1. **本地即数据源**：所有读写先落 localStorage，UI 永不阻塞等待网络。
2. **微同步引擎解耦**：把「合并算法」与「同步调度」抽成通用纯函数 + 控制器，与业务无关，可复用到其他 Vercel + Neon 项目。
3. **单表 JSONB 存储**：用一张 `app_universal_sync` 表存整个学习态，按 namespace 复用，事务 + 行锁防并发覆盖。
4. **保护 Neon 免费额度**：防抖 + 批次权重 + visibilitychange，避免每次写入都打数据库。

## 三、`src/services/syncEngine.ts` —— 通用微同步引擎

设计为**前后端通用**（纯函数无 DOM 依赖，控制器在浏览器侧）。可直接复制到其他项目复用。

### 3.1 三个无冲突合并纯函数（前后端均可 import）

#### `mergeDictionaryByTime<T>(localMap, remoteMap, getTime, getTieBreaker?)`
- 逐 Key 对比两个字典，保留时间戳更大的一方。
- 时间戳相同则用 `getTieBreaker` 决胜（如复习次数 `reps`）。
- 任一端缺失该 Key 直接采用另一端。

#### `mergeAppendOnlyLogs<T>(localArr, remoteArr, getId, getTime, maxLimit = 3000)`
- 追加型日志合并：按 ID Map 并集去重，按时间升序排列。
- 裁剪保留最新 `maxLimit` 条（默认 3000），保护 Vercel Serverless 4.5MB 请求体积限制。

#### `mergeListByIdWithTombstone<T>(localArr, remoteArr, getId, getTime)`
- 列表按 ID 合并，保留更新时间较新的一方。
- 支持软删除（墓碑）：`deletedAt` 较新的项保留，由调用方决定是否过滤展示。

### 3.2 业务级合并 `mergeLearningPayload(local, remote): LearningSyncPayload`

针对 `LearningSyncPayload` 做字段级合并：

| 字段 | 合并策略 |
|------|---------|
| `progress` | `mergeDictionaryByTime`，时间戳 = `updatedAt \|\| lastReviewAt \|\| 0`，tieBreaker = `reps`（确保收藏/笔记随最新修改保留） |
| `logs` | `mergeAppendOnlyLogs`，按 `id` 去重，保留最新 3000 条 |
| `customWords` | `mergeListByIdWithTombstone` 按 `id` 合并，过滤已删墓碑 |
| `customScenarios` | **仅合并 `isCustom === true` 的自建场景**（内置预设不入库），按 `id` 合并 + 墓碑 |
| `achievements` | 已解锁优先（任一端 `unlockedAt` 非空则保留**最早**解锁时间），`progress` 取 `Math.max` |
| `settings` | 取 `updatedAt` 较新者；`onboardingCompleted` 任一端为 `true` 则合并后为 `true` |

### 3.3 `ClientSyncController` —— 前端低频批次同步控制器

保护 Neon 免费 Compute Hours，避免每次本地写入都发请求。

**配置参数（实例化值）**
- `batchThreshold = 10`：累计变更权重达阈值立即 flush（如背满 10 个词）
- `debounceMs = 20000`：静置 20 秒触发一次 flush
- `pullIntervalMs = 120000`：切回前台超过 2 分钟才静默 pull

**核心方法**
- `markDirty(weight = 1)`：累计权重 + 重置防抖计时；权重达标或防抖超时即触发 `flush`。
- `flush(forceOverwrite)`：调用 `onFlush` 推送本地 payload；成功后清脏标记、记 `lastSyncedAt`；失败按网络/服务器分别标 `offline`/`error`。
- `pull()`：调用 `onPull` 拉取合并；记 `lastPulledAt`。
- `subscribe(listener)`：状态变更订阅，UI 用它驱动徽标。
- `destroy()`：移除 `visibilitychange` 监听。

**visibilitychange 行为**
- 切到 `hidden` 且有脏数据 → 立即 `flush`（浏览器可能被挂起）。
- 切回 `visible` 且距上次 pull 超 `pullIntervalMs` → 静默 `pull`。

**并发与防抖保护**
- `flushInFlight` 标志防止并发 flush；防抖计时在 flush 成功后通过 `isDirty` 检查自然失效，不会重复推。

## 四、`src/services/db.ts` —— 数据库扩展

### 4.1 连接池超时
```ts
connectionTimeoutMillis: 15000  // 原 5000，容忍 Neon 冷启动唤醒
```
复用既有 `this.pool`，**未改动 `user_ai_configs` 表及相关方法**。

### 4.2 同步表 `app_universal_sync`
```sql
CREATE TABLE IF NOT EXISTS app_universal_sync (
  namespace   VARCHAR(64) NOT NULL DEFAULT 'memorize_word',
  owner_id    VARCHAR(64) NOT NULL DEFAULT 'default_owner',
  sync_version BIGINT     NOT NULL DEFAULT 1,
  state_data  JSONB       NOT NULL DEFAULT '{}'::jsonb,
  updated_at  TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
  PRIMARY KEY (namespace, owner_id)
);
```
- 单表 JSONB，`namespace` 支持多应用复用同一库。
- `ensureSyncSchema()` 用 `CREATE TABLE IF NOT EXISTS` + `isSyncSchemaInitialized` 标志避免重复建表。

### 4.3 `getSyncState(namespace)`
- `!this.pool` → 抛 `DATABASE_NOT_CONFIGURED`（上层返回 503）。
- 无记录返回 `{ exists: false, syncVersion: 0, stateData: null, updatedAt: null }`。
- 有记录返回解析后的 `stateData`、`syncVersion`、`updatedAt`（毫秒）。

### 4.4 `saveSyncState(incomingData, forceOverwrite, namespace)`
事务流程：
1. `client = pool.connect()` → `BEGIN`
2. `SELECT ... FOR UPDATE` 行锁防并发覆盖
3. 若云端无记录 → `finalData = incomingData`，`nextVersion = 1`
4. 若有记录且 `!forceOverwrite` → `finalData = mergeLearningPayload(incomingData, cloudState)`
5. 若 `forceOverwrite` → `finalData = incomingData`（导入/恢复后强推）
6. `INSERT ... ON CONFLICT DO UPDATE`，`sync_version + 1`
7. `COMMIT`，返回 `{ syncVersion, stateData, updatedAt }`
8. 异常 `ROLLBACK` 并抛错（上层返回 500）

## 五、`server.ts` + `apiClient.ts` —— 同步接口

### 5.1 服务端路由（受全局密码中间件保护）

| 方法 | 路径 | 行为 |
|------|------|------|
| `GET` | `/api/sync/state` | DB 不可用 → 503 `DATABASE_NOT_CONFIGURED`；异常 → 500 `SYNC_READ_ERROR`；正常 → 返回云端状态 JSON |
| `POST` | `/api/sync/state` | 校验 `stateData` 非空对象；DB 不可用 → 503；异常 → 500；正常 → `dbService.saveSyncState(stateData, !!forceOverwrite)` 返回新版本 |

**铁律**：DB 不可用或异常时返回 503/500，**绝不伪装成空数据（HTTP 200）**，防止污染前端状态。

### 5.2 客户端 `apiClient`
- `getCloudSyncState()` → `GET /api/sync/state`
- `pushCloudSyncState(stateData, forceOverwrite)` → `POST /api/sync/state`
- 复用既有 `request()` 封装（自动带 Cookie/Authorization，401 拦截）。

## 六、`src/services/storage.ts` —— 接入同步

### 6.1 控制器挂载
类字段初始化时创建 `ClientSyncController`，绑定：
- `onFlush(forceOverwrite)` → `apiClient.pushCloudSyncState(this.getSyncPayload(), forceOverwrite)`
- `onPull()` → `this.doCloudPull()`（拉取 + 合并 + 回写）

### 6.2 Payload 装配 `getSyncPayload(): LearningSyncPayload`
```ts
{
  settings, progress, customWords,
  customScenarios: [...userScenarios(isCustom===true), ...tombstones],
  logs, achievements, updatedAt
}
```
- **customScenarios 仅含 `isCustom === true`**，内置预设不上云。
- 把本地场景墓碑（`memorize_word_deleted_scenarios`）转成最小 `CustomAiScenario`（带 `deletedAt`）一并上传，传播删除意图。

### 6.3 Payload 回写 `applySyncPayload(payload)`
- 直接写回 `progress` / `logs` / `achievements` / `customWords` 到 localStorage。
- `settings` 直接写（**不走 `saveSettings`**，避免触发新一轮 `markDirty` 与 `updatedAt` 改写覆盖云端值）。
- `customScenarios`：内置预设（未被覆盖的）+ 收到的非墓碑场景组合写回；墓碑单独落到 `DELETED_SCENARIOS_KEY`，并从主列表移除已删项。

### 6.4 写入自动 markDirty（权重分级）

| 方法 | 权重 | 说明 |
|------|------|------|
| `saveSettings` | 2 | 附带 `updatedAt: Date.now()` |
| `saveProgress` / `saveBatchProgress` / `toggleFavorite` / `updateWordNotes` / `addStudyLog` | 1 | 高频小变更 |
| `addCustomWord` / `saveCustomScenario` / `deleteCustomScenario` | 5 | 低频大变更 |

### 6.5 导入/恢复后强推
- `importData`（merge / overwrite 两种模式）成功后调用 `this.syncToCloud(true)`（`forceOverwrite = true`）。
- `restoreSnapshot` 走 `importData`，自动继承该行为。

### 6.6 `clearAllData` 仅清本地
- 清理所有 `memorize_word_*` localStorage 键，**包含快照明细 `memorize_word_snap_data_*`**（原实现漏清）。
- **绝不清空云端 PostgreSQL 与 WebDAV 备份**。
- 不触发 markDirty，避免把空数据误推上云。

### 6.7 场景墓碑（跨设备删除同步）
- 新增 `DELETED_SCENARIOS_KEY = 'memorize_word_deleted_scenarios'`，存 `{ id, deletedAt }[]`。
- `deleteCustomScenario` → 从主列表移除 + 写墓碑 + `markDirty(5)`。
- 墓碑随 payload 上云；`applySyncPayload` 收到带 `deletedAt` 的场景时，合并墓碑并从主列表移除。
- 解决「A 删除场景，B 仍存在」的删除不传播问题。

### 6.8 对外接口
```ts
storage.pullFromCloud()        // 启动/手动拉取合并
storage.syncToCloud(force?)    // 推送（可强制覆盖）
storage.getSyncStatus()        // { status, lastSyncedAt, errorMessage }
storage.subscribeSyncStatus(listener)  // 状态订阅（Navbar/SettingsView 用）
storage.markDirty(weight)      // 外部手动标脏
```

## 七、`src/App.tsx` —— 启动流程与防抢跑

### 7.1 启动防阻塞 + 后台拉取
新增 `initialSyncDone` 状态。认证成功后：
- **立即展示本地缓存数据**（0 等待，UI 不阻塞）。
- 后台调用 `storage.pullFromCloud()`，完成后 `refreshStorageData()` + `setSettings(storage.getSettings())`。
- 无论成功失败，`finally` 中 `setInitialSyncDone(true)`（离线也放行）。

### 7.2 防 Onboarding 抢跑
原逻辑：登录成功且 `!onboardingCompleted` 立即弹引导窗 → 新设备本地为空时会抢先弹窗。
修复：引导窗 effect 改为 `authState === 'authenticated' && initialSyncDone && !settings.onboardingCompleted`，**等首次云端同步检查完成后**才决定是否弹。

### 7.3 防默认初始化覆盖旧设备设置
原逻辑：deck 校验 effect 在认证后立即跑，若 `selectedDeckId` 不匹配则 `handleUpdateSettings` → 会设 `updatedAt=now` 并 markDirty，可能把新设备的默认设置推上云覆盖老设备。
修复：deck 自动校正逻辑 gate 在 `initialSyncDone` 之后（`if (!initialSyncDone) return;`），等云端合并完成再校正。

### 7.4 学习结束触发同步
`StudyView` 的 `onFinishSession` / `onExit` 在 `refreshStorageData()` 后追加 `storage.syncToCloud()`，确保一次学习会话的进度及时上云。

## 十、关键设计决策与避坑

1. **内置预设场景不入库**：`DEFAULT_PRESET_SCENARIOS`（13 个）在 `getCustomScenarios`/`resetToDefaultScenarios` 中会被写进 localStorage，但 `getSyncPayload` 过滤 `isCustom === true`，避免几万字 Prompt 反复传数据库。
2. **敏感信息不入库**：`memorize_word_webdav_config`、WebDAV 密码、Token、AI API Key 均不在 `LearningSyncPayload` 范围内。
3. **DB 错误不伪装空数据**：`/api/sync/*` 在 DB 不可用/异常时返回 503/500，绝不返回 HTTP 200 空数据，防止前端把空状态当真覆盖本地。
4. **事务 + FOR UPDATE**：`saveSyncState` 用行锁防并发写覆盖；`sync_version` 单调递增。
5. **墓碑实现**：场景删除走独立 `DELETED_SCENARIOS_KEY`，不影响主列表语义，避免 `saveCustomScenario` 回写时擦除墓碑。
6. **TDZ 规避**：App.tsx 的初始拉取 effect 放在 `refreshStorageData` 定义之后，避免块级变量先用后声明报错。
7. **applySyncPayload 不走 saveSettings**：直接写 localStorage，避免合并写回时触发 `markDirty` + `updatedAt=now` 把刚拉下来的云端值又覆盖。
8. **超时调大**：Neon 免费版休眠唤醒需 5~8 秒，`connectionTimeoutMillis` 从 5000 调到 15000。

## 十二、可复用性

- 3 个合并纯函数（`mergeDictionaryByTime` / `mergeAppendOnlyLogs` / `mergeListByIdWithTombstone`）无任何业务依赖，可直接复制到其他 Vercel + Neon 项目。

- `mergeLearningPayload` 是业务层示例，新项目替换为自己的 payload 合并逻辑即可。
- `app_universal_sync` 表通过 `namespace` 字段支持多应用共库。
